MeshCore node configurator for NorwayMeshCore node-konfigurator for Norge

Config for Norwegian MeshCore nodes, following the conventions Denmark and the Netherlands use. It targets the EU/UK Narrow preset already running here — 869.618 MHz at 62.5 kHz. Set up a repeater with the regions it relays for, or a companion with the channels for where you are.

Config for norske MeshCore-noder, etter konvensjonene Danmark og Nederland bruker. Den sikter på EU/UK Narrow-preseten som allerede kjører her — 869,618 MHz på 62,5 kHz. Sett opp en repeater med regionene den videresender for, eller en companion med de channels som gjelder der du er.

name — NO-<postnummer> <place>, so a node on Skuiåsen in Bærums Verk is NO-1354 Skuiåsen. 32 bytes, or 24 with a location published; Norwegian letters cost two each. Takes effect after a reboot.

name — NO-<postnummer> <sted>, så en node på Skuiåsen i Bærums Verk blir NO-1354 Skuiåsen. 32 bytes, eller 24 med posisjon publisert; norske bokstaver koster to hver. Trer i kraft etter en reboot.

location — none publishes nothing. position from map publishes the pin you placed, accurate to about a hundred metres. internal gps lets the node find its own position and set its clock, on a build with GPS. Either published mode puts the node on mesh maps and drops the name limit to 24 bytes.

Passwords — guest queries the node, admin reconfigures it. The factory admin password is password. Both stand in the config in the clear.

Passord — guest spør noden, admin konfigurerer den om. Fabrikkpassordet for admin er password. Begge står i klartekst i configen.

What these radio settings doHva disse radioinnstillingene gjør

tx power — set tx, the LoRa chip's output in dBm. Range 1–22, default 22, which is also the firmware's cap. Boards with an amplifier radiate more than this figure. A blank field emits no set tx, leaving the board default.

tx power — set tx, utgangseffekten fra LoRa-brikka i dBm. Område 1–22, standard 22, som også er firmwarens tak. Kort med forsterker stråler mer enn dette tallet. Et blankt felt sender ingen set tx, så kortets standard blir stående.

coding rate — the LoRa error-correction ratio 4/CR, the fourth field of set radio. Default 5: 25% redundancy and the shortest airtime. Each step up adds redundancy and lengthens the transmission by the same amount, so raise it if this node's transmissions are not getting through — 8 doubles both. CR is per node: a receiver reads it from the packet header and decodes any of them. Frequency 869.618 MHz, bandwidth 62.5 kHz and SF 8 are fixed by the mesh.

coding rate — LoRa-forholdet 4/CR for feilkorreksjon, fjerde felt i set radio. Standard 5: 25% redundans og kortest airtime. Hvert steg opp gir mer redundans og forlenger sendingen like mye, så skru den opp hvis sendingene fra denne noden ikke kommer fram — 8 dobler begge deler. CR er per node: en mottaker leser den fra pakkehodet og dekoder hvilken som helst. Frekvens 869,618 MHz, bandwidth 62,5 kHz og SF 8 er låst av meshet.

path.hash.mode — bytes per repeater in a packet's recorded path. 1 byte gives 256 distinct repeater ids and room for 64 hops, 2 bytes 65 536 and 32 hops, 3 bytes 16.7 million and 21 hops. The trade is collision probability against path length.

path.hash.mode — bytes per repeater i pakkas registrerte path. 1 byte gir 256 ulike repeater-id-er og plass til 64 hopp, 2 bytes 65 536 og 32 hopp, 3 bytes 16,7 millioner og 21 hopp. Avveiingen er kollisjonssannsynlighet mot path-lengde.

multi.acks — set multi.acks 1 adds one extra retransmit of every acknowledgement, at that much more airtime. Off in the firmware, and emitted only when on.

multi.acks — set multi.acks 1 legger på én ekstra retransmisjon av hver acknowledgement, mot tilsvarende mer airtime. Av i firmwaren, og sendes bare ut når den er på.

How the back-off works, and how to chooseHvordan back-off virker, og hvordan du velger

Every repeater that hears the same flood waits a random moment before repeating it, so they do not transmit on top of each other. txdelay scales that window for floods, direct.txdelay for direct packets. It buys latency and nothing else — it does not change what the node repeats.

Hver repeater som hører den samme flooden venter et tilfeldig øyeblikk før den sender den videre, så de ikke sender oppå hverandre. txdelay skalerer det vinduet for floods, direct.txdelay for direkte pakker. Det koster latency og ingenting annet — det endrer ikke hva noden videresender.

rxdelay 3 is on every profile, works from the receiving side, and touches floods only — a direct packet is never held. A flood that arrived weakly is held back so a repeater that heard it clearly transmits first, and the weak copy is then dropped as a duplicate.

rxdelay 3 ligger på alle profilene, virker fra mottakersiden og gjelder bare floods — en direkte pakke holdes aldri tilbake. En flood som kom inn svakt holdes tilbake så en repeater som hørte den tydelig sender først, og den svake kopien forkastes som duplikat.

The profiles are indexed by neighbour density. Run neighbors on the node and count the entries with SNR above 0: 4 of 16 is sparse, 19 of 50 is dense.

Profilene er indeksert på nabotetthet. Kjør neighbors på noden og tell oppføringene med SNR over 0: 4 av 16 er tynt, 19 av 50 er tett.

The four profiles are the ones on the wiki (linked from Contact), values and all. The window itself runs from zero to five times txdelay × the packet's own airtime, so a slower packet is given a wider spread. Both delays cap at 2.

De fire profilene er de som står på wikien (lenke under Contact), med verdier og alt. Selve vinduet går fra null til fem ganger txdelay × pakkas egen airtime, så en treg pakke får bredere spredning. Begge delays stopper på 2.

What default scope changesHva default scope endrer

region default — region default <tag> tags what this node sends on its own, which for a repeater is mostly its adverts. It does not change which regions the node relays for; that is the tree on the left. Each button picks the tag at that level for where the node stands — country is no, city is the nearest one. off emits no line at all, so this node's own traffic goes out unscoped and every repeater floods it. That is the setting to use until the repeaters around you carry regions.

region default — region default <tag> tagger det denne noden sender selv, som for en repeater stort sett er advertene dens. Det endrer ikke hvilke regioner noden videresender for; det er treet til venstre. Hver knapp velger taggen på det nivået for der noden står — country er no, city er den nærmeste. off sender ingen linje i det hele tatt, så nodens egen trafikk går ut unscoped og hver repeater flooder den. Det er innstillingen å bruke til repeaterne rundt deg bærer regioner.

unscoped floods — what this repeater does with floods carrying no region tag. allow emits region allowf *, the firmware default, restated in case the node had it denied. cap keeps that line and adds set flood.max.unscoped, limiting untagged floods to that many hops. deny emits region denyf * instead, dropping them — which cuts off every node that has not set regions yet.

unscoped floods — hva denne repeateren gjør med floods uten region-tagg. allow sender region allowf *, firmwarens standard, gjentatt i tilfelle noden hadde den denied. cap beholder den linja og legger til set flood.max.unscoped, som begrenser utaggede floods til så mange hopp. deny sender region denyf * i stedet og forkaster dem — noe som skjærer av enhver node som ikke har satt regioner ennå.

            How these channels work, and who else is on themHvordan disse channels virker, og hvem andre som er på dem
            
The name is the channel. A channel starting with # derives its
               key from its own name, so everyone who types #baerum lands on the same
               one and there is no key to hand out. The app accepts a-z,
               0-9 and - only, hence ostlandet and
               baerum.

            
Navnet er channelen. En channel som starter med # utleder
               nøkkelen fra sitt eget navn, så alle som skriver #baerum havner på den
               samme, og det finnes ingen nøkkel å dele ut. Appen godtar bare a-z,
               0-9 og -, derav ostlandet og
               baerum.

            
So they are not private. Anyone who knows the name can derive the key. Treat
               them as an open calling frequency; for something private, make a channel with a random
               secret and hand that out yourself.

            
Så de er ikke private. Alle som kjenner navnet kan utlede nøkkelen.
               Behandle dem som en åpen kallefrekvens; skal noe være privat, lag en channel med en
               tilfeldig secret og del den ut selv.

A node near a border also relays for the other side, and these say
               how near counts: 5 km from the next fylke and the node carries that fylke too — a

0 turns a level off. Kommune starts there: at this mesh size its
               regions have almost no members to filter, and its tags are the longest.

            
0 slår av et nivå. Kommune starter der: i denne
               meshstørrelsen har regionene dens nesten ingen medlemmer å filtrere, og taggene er de
               lengste.

          

          
A region tells repeaters which floods to pass on. It does not limit who you can
             reach — every node carries eu and no — and it cuts nobody off:
             tags only add, and untagged traffic keeps flowing unless you pick
             region denyf * under unscoped floods. What narrow tags do is keep a
             local channel from flooding the country.

          
En region forteller repeatere hvilke floods de skal sende videre. Den begrenser
             ikke hvem du kan nå — hver node bærer eu og no — og den skjærer
             ingen av: tagger legger bare til, og utagget trafikk går som før med mindre du velger
             region denyf * under unscoped floods. Det smale tagger gjør, er å
             hindre en lokal channel i å floode hele landet.

          
A kommunenummer is not a postnummer. Both are four digits and unrelated: the
             node name uses the postnummer, the region tags use the kommunenummer, so
             NO-1354 Skuiåsen tagged no-3201 is correct. The first two
             digits of a kommunenummer are its fylke, so no-3201 is inside
             no-32 by construction.

          
Et kommunenummer er ikke et postnummer. Begge har fire siffer og har
             ingenting med hverandre å gjøre: nodenavnet bruker postnummeret, regiontaggene
             bruker kommunenummeret, så NO-1354 Skuiåsen tagget no-3201 er
             riktig. De to første sifrene i et kommunenummer er fylket, så no-3201 ligger
             inni no-32 av konstruksjon.

          
          
          

            

            
            fylkesnummer

A tag means "relays for", not "is in". A node inside Oslo's city radius carries
             no-oslo from a ridge well outside town, one between two cities carries both,
             and one 5 km from Buskerud carries no-33 too. Expect neighbours across
             water — over water is the best path a radio gets.

          
En tagg betyr "videresender for", ikke "ligger i". En node innenfor
             byradiusen til Oslo bærer no-oslo fra en ås godt utenfor byen, en mellom to
             byer bærer begge, og en 5 km fra Buskerud bærer no-33 også. Regn med
             naboer over vann — over vann er den beste veien en radio får.

          
The bare three-letter tag is the single nearest airport — osl,
             bgo, trd — with no no- in front, because an
             airport code is already unique worldwide. Landsdel, fylke, kommune, city and airport are
             independent overlays under no, not a nesting, so every tag is listed in
             full; the codes are current since the county reform of January 2024.

          
Den bare tre-bokstavstaggen er den ene nærmeste flyplassen — osl,
             bgo, trd — uten no- foran, fordi en flyplasskode
             allerede er unik verden over. Landsdel, fylke, kommune, city og flyplass er uavhengige
             lag under no, ikke en nøsting, så hver tagg listes i sin helhet; kodene er
             gjeldende siden fylkesreformen i januar 2024.

          

        

      

    


  


  
  

    

      
      
About MeshNOOm MeshNO

      
A configurator for Norwegian MeshCore nodes, and a proposal for how
         they should scope what they relay.

      
      
MeshNO er en konfigurator for oppsett av MeshCore-noder i
         Norge: radio og frekvens (869,618 MHz på EU/UK Narrow), timing,
         navn og regioner som én ferdig kommandoblokk å lime inn. Sett noden på kartet,
         så får du regionene en repeater skal videresende for, og hvilke channels du
         trenger der du står.

    


    
    

      
Why it exists

      
Hvorfor den finnes

      
Around a hundred MeshCore nodes already relay in Norway. Almost none of
         them set a region, and there has been no agreed list of names to set — so every
         repeater carries every flood, and a message meant for one fylke crosses the country.
         MeshCore has had the mechanism since firmware 1.15. What was missing was a convention.

      
Rundt hundre MeshCore-noder videresender allerede i Norge. Nesten
         ingen av dem har satt en region, og det har ikke vært noen omforent liste med navn å
         sette — så hver repeater bærer hver eneste flood, og en melding ment for ett fylke
         krysser hele landet. MeshCore har hatt mekanismen siden firmware 1.15. Det som manglet,
         var en konvensjon.

      
This page is one. It exists to make a single set of region names the
         easiest thing to copy correctly, rather than a hundred operators each improvising
         their own — which is the outcome that cannot be undone later.

      
Denne siden er et forslag til én. Den finnes for å gjøre ett sett
         regionnavn til det enkleste å kopiere riktig, framfor at hundre operatører finner opp
         sitt eget — utfallet som ikke lar seg rette opp i etterkant.

The convention

      
Konvensjonen

      
Five levels, all of them siblings under no rather than
         nested — a city's radius crosses fylke borders, and the firmware matches region names
         exactly, so tree position never meant inheritance anyway.

      
Fem nivåer, alle søsken under no framfor nøstet — en
         bys radius krysser fylkesgrenser, og firmwaren matcher regionnavn eksakt, så plassering
         i treet har uansett aldri betydd arv.

      
      
eu
└─ no          everything in Norway
   ├─ no-ost   landsdel   five of them
   ├─ no-03    fylke      the 2024 codes
   ├─ no-0301  kommune    fylke code, then kommune
   ├─ no-oslo  city       inside a city radius only
   └─ osl      airport    IATA, and bare

      
eu
└─ no          alt i Norge
   ├─ no-ost   landsdel   fem av dem
   ├─ no-03    fylke      2024-kodene
   ├─ no-0301  kommune    fylkeskode, så kommune
   ├─ no-oslo  by         kun innenfor en byradius
   └─ osl      flyplass   IATA, og bar

      
Norway sits under eu even though it is EEA and not EU, and
         the tags are ASCII, so Østlandet is no-ost. Both mirror what the Danish
         and Dutch communities already run; matching a neighbour was judged worth more than
         being right alone.

      
Norge ligger under eu selv om vi er EØS og ikke EU, og
         taggene er ASCII, så Østlandet blir no-ost. Begge deler speiler det danske og
         nederlandske miljøet allerede kjører; å være lik naboen ble vurdert som mer verdt enn å
         ha rett alene.

What it is not

         before deploying a node you cannot easily reach again.

      
Den er ikke tilknyttet MeshCore-prosjektet, og regionnavnene på den
         er et forslag og ikke en standard — de holder bare så lenge operatører fortsetter å bruke
         dem. Les blokka før du limer den inn, og sjekk kommandoene mot
         docs.meshcore.io
         før du setter ut en node du ikke kommer lett til igjen.

The convention itself

      
Selve konvensjonen

      
Whether these region names are the right ones, or should exist at all,
         is a question for the operators who would run them — not for this page. That
         conversation happens on the Norwegian MeshCore Discord, and it is where a change to
         the convention has to be agreed before it is worth building.

      
Om disse regionnavnene er de riktige, eller bør finnes i det hele
         tatt, er et spørsmål for operatørene som skal kjøre dem — ikke for denne siden. Den
         samtalen foregår på den norske MeshCore-Discorden, og det er der en endring i
         konvensjonen må avtales før det er verdt å bygge den.

Everything this page does not cover

      
Alt denne siden ikke dekker

      
The Norwegian mesh wiki covers Meshtastic, MeshCore and Reticulum.
         For MeshCore it has the frequency rules for the 869 MHz band and what they mean for
         antenna choice, the LoRa parameters used here, getting started from a kit or from parts,
         suggested repeater placements, and a CLI cheat sheet. It is written in Norwegian.

      
Den norske mesh-wikien dekker Meshtastic, MeshCore og Reticulum. For
         MeshCore har den frekvensreglene for 869 MHz-båndet og hva de betyr for antennevalg,
         LoRa-parameterne som brukes her, å komme i gang fra kit eller fra deler, forslag til
         repeater-plasseringer, og en CLI-jukselapp.

      
It also has a page of recommended repeater settings, which is the
         same ground this page covers. Where the two disagree, the wiki is the one maintained by
         more people than this page is.

      
Den har også en side med anbefalt oppsett og innstillinger på
         repeater, som er den samme grunnen denne siden dekker. Der de to er uenige, er wikien den
         som vedlikeholdes av flere folk enn denne siden.

      
meshwiki.no
